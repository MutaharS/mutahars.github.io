01 / Capital One / Platform engineering

Modernizing event-driven data workflows

Legacy ETL was costly to run and expensive to support. I re-engineered the workflows into a hybrid AWS and declarative Spark architecture, then added automation and telemetry so the platform could be operated with clearer signals.

~$360KEstimated annual cost reduction
>50%Less routine maintenance effort
Days → minutesIncident response time

What changed

The architecture moved legacy ETL into an event-driven flow built around Kinesis Firehose, AWS Lambda, S3, Glue, and an in-house declarative Spark framework. Self-healing automation handled routine failure modes. New Relic instrumentation reported pipeline duration and custom error codes, with an alert when error rates exceeded 5% within a rolling 10-minute window.

Why it mattered

The changes drove an estimated $360K in annual cost reductions, cut routine maintenance effort by more than half, and brought incident response from days to minutes. The telemetry gave engineers useful operational visibility without requiring them to trace every orchestration layer manually.

02 / Capital One / Data products

One trusted lender report from four source formats

Auto-lending partners sent funding reports in different formats. The process team needed a consistent, auditable view of funded loans, but monthly reconciliation required a full day of manual work.

My approach

I designed a serverless ingestion framework that recognized each incoming file, preserved the raw data, routed each report format through its own transformation path, and produced a unified lender report. The design made the output consistent while retaining the source data needed for auditability and troubleshooting.

Outcome

The pipeline replaced a full-day monthly manual cycle and supported accurate, timely collection of more than $200K in monthly revenue. In related platform work, I established ODCS-based data contracts with source-level checks for schema, valid ranges, and nullability to protect downstream data quality.

03 / Abbott Labs / Health data

Faster, lower-cost processing for privacy-sensitive data

Multi-terabyte PII and non-PII datasets required reliable transformation and de-identification. I led a migration from AWS jobs to multi-hop Databricks Delta Live Tables workflows.

80%Runtime reduction
77%Job cost reduction
TerabytesPII and non-PII processed

Design and delivery

The workflow ingested, transformed, and de-identified data across multiple stages. I worked with business users to turn clinical and operational requirements into tested data models, and created synthetic datasets that reproduced production patterns for load and schema-drift testing.

Operational quality

I built job-health and data-anomaly reporting to make pipeline behavior easier to inspect. Separate performance work on a critical Python JSON batch job reduced runtime by nearly 99% through caching and memory-efficient processing.

04 / Capital One / Application services

High-throughput endpoints for dealer credit applications

I developed new hard-credit application endpoints for the Dealer CRM using Java and Spring Boot. The work reduced CRM drop-off and contributed to a loan-funding funnel worth more than $10B.

The endpoints addressed friction in a product-facing workflow. This work sits alongside my data platform experience and reflects my interest in software that improves both the customer journey and the systems behind it.
